# Архитектура Umbra Vault

```text
app/
  main.py          Запуск Qt и подключение контроллера
  core/            Записи и фильтрация, без Qt
  services/        Генерация паролей, без Qt
  ui/
    controller.py  Состояние хранилища и интеграция с Qt
    vault_job.py   Фоновое открытие и сохранение
    qml/           Окно, экраны и диалоги
    components/    Элементы управления и пиктограммы
    themes/        Палитры и единые параметры оформления
  security/        Заголовок, Argon2id и AEAD
  storage/         Файловое хранилище и локальные настройки
assets/
docs/
tests/
```

## Данные и операции

Контроллер запускает одну операцию с хранилищем за раз. После успешного сохранения фоновой задачей он обновляет модель и показывает подтверждение. При ошибке остаётся прежняя модель, а редактор записи можно использовать для повторной попытки. При блокировке контроллер отбрасывает текущую сессию и результат ожидающей операции. Подробности формата и границ защиты описаны в [модели угроз](../SECURITY.md).

Демосессия доступна при запуске из исходников с параметром `--demo`. Сборка для Windows исключает модуль демонстрационных данных. Настройки интерфейса и прежнее оформление образцов остаются в локальных настройках.

## Интерфейс

Единая палитра задаёт поверхности, границы, фокус и фиолетовый акцент для светлой и тёмной тем. Основной экран, настройки и диалоги загружаются по необходимости. Qt выставляет размеры в логических пикселях. Радиус элементов составляет 8–12, переходы интерактивных состояний занимают 140 мс и отключаются настройкой уменьшения движения. Текущая поверхность окна непрозрачная. Mica/Acrylic требует отдельной проверки интеграции Qt с DWM.

## Исторические замеры прототипа

На Windows x64 с Python 3.12.14 и Qt 6.12.0 проверена загрузка стартового экрана. Семь тестов покрывают загрузку QML, сценарии создания и открытия демосессии, редактирование, поиск, генерацию, настройки, блокировку и условную очистку буфера. Проверено включение ресурсов QML в Python wheel.

Отрисовка проверена с оконной платформой Qt `windows`. Масштаб задавался через `QT_SCALE_FACTOR` при отдельном запуске процесса для каждого значения. Время считалось с момента перед импортом Qt до показа окна. Рабочий набор памяти измерялся после открытия образца из шести записей.

| Масштаб Qt | Показ окна, мс | Рабочий набор, МиБ |
| --- | ---: | ---: |
| 100% | 621 | 141,7 |
| 125% | 592 | 138,3 |
| 150% | 617 | 140,0 |
| 200% | 620 | 142,3 |

Результаты относятся к этому компьютеру. Проверка экранного диктора, системного DPI на нескольких мониторах и чистой системы остаётся на последующие этапы.
